# 小说抓取全流程指引（主索引）

## 流程概要

```
目标确认(含备用站准备) → 网站结构分析 → 逐章抓取(主站) → 组装输出 → 污染抽检 → 污染定位与修复(备用站补齐) → 管道清洗 → 汇报归档
```

## 子指引索引

每个步骤对应一个子指引文件，存放在 `fetch/` 目录下。**只在执行该步骤时加载对应文件**，不要一次加载全部。

| 步骤 | 子指引文件 | 内容概要 | 何时加载 |
|------|-----------|---------|---------|
| 步骤 0 | `fetch/step-0-target.md` | 目标确认、技术路线选择、备用站点准备与验证 | 用户提出抓取请求时 |
| 步骤 1 | `fetch/step-1-analysis.md` | 目录页HTML获取、编码检测、目录结构分析、正文页结构分析 | 确定目标URL后 |
| 步骤 2 | `fetch/step-2-toc.md` | 完整解析章节列表、分页目录处理、章节列表验证 | 网站结构分析完成后 |
| 步骤 3 | `fetch/step-3-fetching.md` | 核心抓取函数、并行抓取策略、空章节检测、异常长度检测、多页章节处理、浏览器降级、广告过滤 | 章节列表就绪后 |
| 步骤 4 | `fetch/step-4-assembly.md` | 全文组装、污染抽检(4.5)、污染定位与修复(4.6)、跨书排版污染修复(4.7)、源站数据损坏修复(4.8) | 全量抓取完成后 |
| 步骤 6 | `fetch/step-6-report.md` | 汇报结构、网站速查表、跨站ID发现、脚本化建议 | 清洗完成后汇报时 |

## 加载规则

```
1. 收到抓取请求 → 先读本索引文件
2. 执行到某步骤 → 只读该步骤对应的子指引
3. 切换步骤 → 读新的子指引，上一个步骤的内容不再需要
4. 跨步骤引用（如步骤4.6需要备用站信息）→ 读对应子指引的特定章节，不需要读全文件
5. 常见网站结构速查 → 在 step-6-report.md 末尾，需要时单独查找
```

## 与清洗管道的关系

- 抓取完成后，原始 TXT 进入清洗管道
- 清洗指引主索引：`../小说清洗/index.md`
- 清洗子指引：`clean/` 目录
- 先抓取 → 后清洗，不要跳过

## 工具链

| 工具 | 用途 | 路径/命令 |
|------|------|-----------|
| `curl` | HTTP 请求 | 系统自带 |
| `python3` + `html.parser` | HTML 解析 | 标准库 |
| `bs4` (BeautifulSoup) | HTML 解析增强 | `python3 -c "from bs4 import BeautifulSoup"` |
| `agent-browser` skill | 浏览器自动化 | Skill 工具调用 |
| `clean_novel.py` | 清洗单文件 | `~/.claude/tools/clean_novel.py`（本地路径） |
| `batch_clean.py` | 批量清洗 | `~/.claude/tools/batch_clean.py`（本地路径） |
| `clean_filenames.py` | 文件名清洗 | `~/.claude/tools/clean_filenames.py`（本地路径） |

## 核心原则

1. **先分析后抓取**：先摸清网站结构再动手，不盲目猜测
2. **礼貌抓取**：合理延时、设置 User-Agent、不过度请求
3. **降级有序**：HTTP → 浏览器，逐级降级
4. **保留原始**：始终保留未经修改的原始抓取文件
5. **管道对接**：抓取只是上游，清洗才是出品质量的保障
6. **污染闭环**：全书抓取完成后必须抽样语义检查，发现污染则从备用站补齐
7. **增量积累**：新站点的分析结果记录到速查表，后续复用
8. **Python stdout 缓冲**：抓取脚本必须用 `python3 -u` 或 `flush=True`，避免后台运行时输出不可见
