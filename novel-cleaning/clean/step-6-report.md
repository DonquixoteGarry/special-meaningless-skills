## 核心原则

- **先分析后动手**：不要上来就改，先全面扫描再说
- **推理驱动**：拼音残留必须用上下文推理正确汉字，不能猜，不能随意替换
- **闭环验证**：改完规则必须重跑 → 验证 → 确认无残留
- **增量可维护**：新发现的模式追加到 JSON 规则文件，不改脚本
- **一次一批**：只修复确定能修的，不确定的先标注，避免引入新错误

## 规则文件结构参考

```json
{
  "_version": "YYYY-MM-DD",
  "ad_patterns": [
    ["正则表达式", "替换文本"],
    ["(?<=[\\u4e00-\\u9fff])i(?=[\\u4e00-\\u9fff])", "日"]
  ],
  "line_remove_patterns": [
    "正则字符串（匹配的行整行删除）",
    "笔趣阁.*?提供下载"
  ],
  "encoding_fixes": {
    "损坏文本": "正确文本",
    "l物": "零物"
  },
  "chapter_re": "^第(\\s*[一二三四五六七八九十百千零\\d]+\\s*)([章节])\\s*(.*)$",
  "volume_re": "^第(\\s*[一二三四五六七八九十百千零\\d]+\\s*)卷\\s*(.*)$",
  "separator_re": "^[=\\-_\\*]{10,}$",
  "alt_chapter_patterns": [
    "^(\\d{3,})\\s+(.*)$",
    "^=== (\\d+)【(.+)】\\s*===\\s*$"
  ]
}
```

## 清洗管道执行顺序（代码逻辑）

```
1. ad_patterns 全文正则替换
2. HTML 标签剥离 (<[^>]+>)
3. encoding_fixes 精确字符串替换 (text.replace)
4. 按行处理：
   a. 行删除判断 (line_remove_patterns + 裸URL + 分隔线)
   b. 章节格式统一 (chapter_re + volume_re)
   c. 空行规范化（压缩到最多连续2个空行）
5. 质量抽查（3轮 × 20段 = 最多60个样本点）
6. LLM 语义样本提取（3轮 × 5段 × 1000字）
7. batch_clean 额外流程：
   a. 文件名清洗（移除网站标识、书名号）
   b. 全量扫描 full_scan()
```
