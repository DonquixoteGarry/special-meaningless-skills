## 步骤 2：拼音残留清洗（Pinyin Residue Cleaning）

### 2.1 全量扫描拼音字母

在**清洗后**的输出文件上扫描：

```python
import re
with open('清洗后.txt', 'r') as f:
    lines = f.readlines()

for i, line in enumerate(lines):
    for m in re.finditer(r'[一-鿟》）」]([a-zāáǎàōóǒòēéěèīíǐìūúǔùǖǘǚǜ])[一-鿟《（「]', line):
        print(f'L{i+1}: {line.strip()}')
```

### 2.2 对每种字母逐个推理

对每个找到的字母类型：

**步骤 A：取上下文**
使用 30-50 字的上下文判断。需要搜索**该字母所有出现位置**，不要只看第一处。

**步骤 B：分类判断**

**类别 1：正常内容（不需要处理）**
- `c城` — 小说中的坐标代码（如"C城"），属于剧情设定
- `o` 在佛教咒语中 — 梵文转写（"哪o哞哆嘛娑诃"），属于正常跨语言内容
- 英文人名/地名缩写（`Mr.`、`Dr.` 中的点可被剥离后剩下单字母）

**类别 2：编码拼音损坏（需要修复）**
- 特征：单字母出现在整个语义词中，`l物`、`t望塔`、`h锅补盆`
- 修复方法：分析上下文，推理正确汉字
- 推理线索：
  - **引用的古诗文** → 查原句对照（eg. 高适诗、尚书、诗经、国语）
  - **历史人名** → 根据字号/著作/并称反推（eg. "李b李恕谷" → 李塨）
  - **贸易/专业术语** → 根据语境和行业知识判断（eg. "l物" → 零物，零碎物品）
  - **反复出现的同一模式** → 大概率是同一字符（eg. "l物" 出现 37 次，都是同一含义）
  - **代码中的 encoding_fixes 已有模式** → 参考规则文件中已有的替换来判断新模式

**类别 3：字节深度损坏（无法恢复）**
- 特征：字母出现在多处不同上下文中且含义不同（eg. "u" 在古诗、人名、古文中含义各不相同）
- 或出现在大段乱码段落中（整段有多个不可识别的字符）
- 标注出来向用户说明

**类别 4：声调字母（带 ā á ǎ à 等）**
- 声调字母（`āáǎàōóǒòēéěèīíǐìūúǔùǖǘǚǜ`）总是损坏，因为标准中文中不会出现带声调的 ASCII 字母
- 但在大段乱码中出现时（连续多个不可识别字符），单独修复单个字母没有意义
- 若无完整上下文，标注为「深度损坏段落中的声调字符」

**步骤 C：追加到规则文件**

对「类别 2」中的确定性修复，追加到 `encoding_fixes`：

```json
{
  "l物": "零物",
  "t望": "眺望",
  "h锅": "焊锅",
  "翠h": "翠含",
  "之m也": "之甿也",
  "一g痛": "一股痛"
}
```

规则追加逻辑：
- `encoding_fixes` 用的是 **精确字符串匹配**（`text.replace()`），不是正则
- key 不要太短（`"h"` 太短可能误伤正常英文），带上上下文（`"h锅"`）
- 避免 key 过于通用（`"i"` 应使用 ad_patterns 中的正则，而不是 encoding_fixes）
