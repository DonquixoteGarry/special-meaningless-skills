## 步骤 5：验证（Verification）

### 5.1 全量行级扫描（使用代码中的 full_scan）

代码中的 `full_scan()` 在完成清洗后会自动运行，检查逻辑包括：

1. **行删除模式残留**：对每一行，用 `line_remove_patterns` 中所有模式扫描
2. **广告替换模式残留**：对每一行，用 `ad_patterns` 中所有正则扫描
3. **裸 URL 行**：`^https?://\S+$`

如果发现残留，说明规则需要补充。

### 5.2 自行验证拼音残留

在重跑后的输出文件上再次运行全量拼音字母扫描：

```python
residues = re.findall(r'[一-鿟》）」][a-zāáǎàōóǒòēéěèīíǐìūúǔùǖǘǚǜ][一-鿟《（「]', text)
```

对比步骤 2 中的数据：
- 已修复的模式应从列表中消失
- 剩余残留数量应比上一轮减少

### 5.3 文件完整性检查

- 文件末尾应未被意外截断（`tail -5`）
- 章节总数应和步骤 0 中统计的基本一致
- 文件大小的剧烈变化（>10%）可能意味着内容被误删

### 5.4 小说内容污染验证（0.7 的闭环）

对比步骤 0.7 中发现的污染关键词，确认清洗后已消失：

```bash
for term in "韩宥" "陈铭" "卡卡西" "电脑"; do
    grep -c "$term" 清洗后.txt || echo "已清除"
done
```

如果污染仍存在，说明源文件未被修正，**不要继续加清洗规则**（清洗规则解决不了语义污染），应：
1. 定位污染章节号（`grep -n "污染词" 源文件` → 找到最近的章标题行号）
2. 从备用站重新抓取这些章节（参见小说抓取指引 4.7 节）
3. 替换源文件中被污染的章节段落
4. 回到步骤 1 重新清洗

### 5.5 异常长度验证（0.8 的闭环）

清洗后重新运行步骤 0.8 的检测代码，对比清洗前后的结果：

**空/过短章节变化：**
- 清洗后新增的空章节 → 说明清洗规则误删了整章内容（如 `line_remove_patterns` 过度匹配），需修复规则后重跑，**不可跳过**
- 清洗前存在、清洗后仍在的空章节 → 源文件缺陷，标记后进入抓取修补流程

**异常长度章节变化：**
- 清洗后新增的异常长度章节 → 检查清洗是否误删了大量内容导致章节偏短
- 清洗前后均存在的异常长度 → 源文件问题，回抓取阶段用备用站替换

**对比清洗前后的异常长度列表，确认：**
- 原来偏长（含污染词）的章节在替换后长度恢复正常 ✓
- 原来偏短（占位章）的章节在替换后长度恢复正常 ✓
- 没有因为清洗而新产生的异常章节 ✓

### 5.6 清理临时文件

删除以下中间产物，**只保留** `{目录_clean}/源文件名.txt`：

| 文件 | 来源 | 处理方式 |
|------|------|---------|
| `*.bak` | clean_novel 的备份（仅单文件运行时生成） | 删除 |
| `*_clean.txt`（在源目录） | 单文件 `clean_novel.py` 的输出 | 删除 |
| `*.llm_samples.json` | 质量抽检的 LLM 样本 | 删除 |
